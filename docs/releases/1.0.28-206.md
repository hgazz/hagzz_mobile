# Customer app 1.0.28+206 — startup recovery candidate

This candidate addresses startup/retry defects found while investigating the Google Play “Unresponsive app” rejection. The reviewer screenshot alone does not establish the underlying Android ANR or prove these were its cause.

Historical inspection of version 204 (`d766721`) confirmed an unbounded `FirebaseMessaging.instance.getToken()` await before `runApp`. A slow/unavailable notification token could therefore leave the native launch screen visible. Version 205 already moved notification registration after UI startup and bounded token retrieval; 206 retains those fixes. This is a concrete failure path consistent with the screenshot, not a reproduction of Google's device failure.

## Changes

- Draw the startup screen before invoking plugin/storage initialization.
- Reuse unfinished initialization after a timeout: `Future.timeout` does not cancel plugin calls, so retries must not open Firebase/Hive/storage concurrently.
- Show loading feedback during a retry instead of retaining the previous error screen.
- Raise the version to 1.0.28+206. Keep Android compile/target SDK 36 and minimum SDK 24.

The actual bundle manifest confirms package `com.unlimitedhagzz.hagzz`, version 1.0.28+206, min SDK 24, compile/target SDK 36, and all three Android ABIs.
